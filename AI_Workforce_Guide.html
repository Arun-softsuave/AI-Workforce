AI Workforce

An AI team member that watches your Jira tickets, learns your codebase, prepares plans, code and tests, and then waits for your approval. Here is what happens from unzipping the plugin to a pull request.

Onboarding stages

Setup asks one thing at a time, mostly as options you click. Stop anytime and run aiw setup to pick up where you left off.

  1. Prerequisites check

    Node 22.13+, Git, Claude Code. aiw doctor

  2. Background service

    Starts at login, no admin rights needed.

  3. Model access

    Claude Code login, an API key, or Mock for a free dry run.

  4. Your roles

    Backend, frontend, full-stack, QA, DevOps, BA, PM or UI/UX. Roles pick the playbooks.

  5. Connect tools

    Jira (sign in with Atlassian in the browser), GitHub (reuses gh), plus Slack, Teams, Notion, Figma if you use them.

  6. Notifications

    Two-way Teams bot, Slack, desktop alerts. Then aiw notify test.

  7. Projects

    Jira key + repo + local folder. Backend and frontend repos can be grouped under one key.

  8. Product documents

    Optional PRD or BRD (.pdf, .docx, .md). Can stay private on your PC.

  9. Build the Brain

    It studies the repos and writes a Handbook. You review it and confirm.

  10. Go live

    aiw live. It starts watching your Jira.

Secrets never go through the chat. Keys and tokens are entered on a local page (127.0.0.1) and stored in your OS credential vault.

After go-live

How a ticket becomes a pull request

Each step is a fixed recipe called a playbook. Code controls the order; agents do the thinking inside each step. Cheap models handle small jobs and the large model only plans.

No AI tokensAI agentsLoops with a limitYou decide
  1. J

    Watch Jira

    Polls every 2 to 5 minutes and compares with the last snapshot, so each change is handled once.

    0 tokens
  2. T

    Triage

    Is it a bug or feature, how big, is it clear? Unclear tickets come back to you as a question. Size L asks before starting.

    small model
  3. W

    Isolated workspace

    A separate git worktree. Your own checkout is never touched.

    0 tokens
  4. C

    Context pack from the Brain

    Relevant Handbook facts, code map, past tasks and PRD sections.

    search
  5. P

    Analyse and plan

    Then a fresh-eyes reviewer checks the plan. In plan autonomy you approve here before any code.

    large model
  6. I

    Implement and test

    Write code, run the repo's own tests, lint and type checks. Repeats up to 3 times.

    max 3
  7. R

    Code, security and QA review

    Three reviewers in parallel. Up to 2 rounds of fixes.

    max 2
  8. F

    Final checks

    Rebase on the base branch, secret scan, final tests, strip any AI mentions, write the report.

    0 tokens
  9. A

    Your approval

    Notified in Teams, Slack, desktop or Claude Code. Waiting costs nothing. Reject with feedback and it re-runs.

    you
  10. PR

    Draft pull request

    Pushed with your git identity, bound to the exact commit you approved. Then it writes the diary and updates the Brain.

    0 tokens

Other roles use other playbooks: QA gets test plans, DevOps gets CI-failure fixes, BAs get user stories, PMs get a daily digest, designers get design reviews.

Per project

The Brain: how it learns

The Brain is the project's memory. Every task reads from it and every finished task adds to it. The team reviews what it learns before it becomes trusted.

Map

Where things live in the code: modules, files, symbols.

Handbook

Architecture, standards, decisions, glossary. Stored in the repo under .ai-workforce/knowledge/.

Diary

What each finished task did and why.

Index

Full-text search across all of it, plus your product documents.

Onboarding

Learn

Reads the repos, history and docs. Detects team conventions.

Every task

Use

Pulls only the relevant facts into the agents' context.

After a task

Propose

Suggests new facts it discovered, marked unverified.

Daily

Refresh

Re-maps changed code and re-detects branch, commit and PR style.

Each fact moves through: unverified→ team confirms →verified · laterreplacedordisputed

Unverified facts are hints, not rules. Agents check them against the code. If code contradicts a fact, it is flagged for review instead of being silently rewritten.

Built in, not optional

Safety rules

  • Nothing publishes without youApproval is tied to the exact commit. If the code changes, it asks again.
  • Never merges or deploysIt opens draft PRs only. Agents are not allowed to run git push.
  • No AI attributionCommits use your git identity. Messages, PR text and Jira comments are checked for Claude or AI mentions.
  • Stays on your machineData lives in ~/.ai-workforce. Work runs while your computer is on and catches up after sleep.
  • Budget guardDaily token limits pause work instead of overspending. aiw cost shows spend.
  • Tickets are dataText from tickets and documents is never treated as instructions.
Remove everything with aiw uninstall --purge, then /plugin uninstall ai-workforce in Claude Code.
